## 📌 Project Overview

This project demonstrates the complete **RTL-to-GDSII implementation flow** of a processor execution unit. Starting from a 32-bit instruction, the design decodes the instruction, reads operands from a 32×32 Register File, performs an arithmetic or logical operation in the ALU, and writes the result back to the destination register.

**Current stage:** the Instruction Decoder, Register File (Version 2) and ALU are integrated in the `execution_unit` top module and the complete datapath has been functionally verified (10 of 10 ALU operations pass in Cadence Xcelium / SimVision). The RTL has been **synthesized with Cadence Genus** on a 90 nm standard-cell library, and the **area report has been analyzed**: the design maps to 5373 standard cells. The next phase is gate-level, timing and power analysis, followed by physical design in Cadence Innovus.

The entire flow — from RTL design through synthesis, physical design, and timing closure — is implemented using industry-standard Cadence EDA tools on Linux.

**Data flow**


### Execution Unit

`execution_unit` instantiates the decoder, register file and ALU and adds a write-back select that shares the Register File's single write port between normal write-back and register initialization. All ten ALU operations have been verified through this integrated datapath (see [Functional Verification](#-functional-verification)).

| Port | Direction | Width | Description |
|------|-----------|-------|-------------|
| `clk` | Input | 1 | System clock |
| `rst` | Input | 1 | Reset, applied to the Register File |
| `reg_write` | Input | 1 | Normal write-back enable |
| `init_write` | Input | 1 | Register-initialization enable (simulation / verification) |
| `init_addr` | Input | 5 | Register to initialize |
| `init_data` | Input | 32 | Initialization value |
| `instruction` | Input | 32 | Instruction word |
| `alu_result` | Output | 32 | ALU result |
| `zero` | Output | 1 | ALU zero flag |

### Cadence Genus Overview

Cadence Genus is a logic synthesis tool. It translates RTL into a gate-level netlist built from the cells of a target standard-cell library, optimizing the result against the timing constraints. In this project it runs through a single automated script, `synthesis/scripts/run_genus.tcl`.

| Stage | Command | What it does |
|-------|---------|--------------|
| Generic synthesis | `syn_gen` | Converts the elaborated RTL into generic logic, independent of any library |
| Technology mapping | `syn_map` | Maps the generic logic onto the 90 nm standard cells |
| Logic optimization | `syn_opt` | Optimizes the mapped netlist against the timing constraints |

## 📐 Area Analysis

> **Status:** ✅ Area report analyzed (Day 9). Gate-level, timing and power analysis will follow in upcoming updates.

### Purpose

Area analysis shows how the RTL was translated into standard cells and how much cell area the synthesized design occupies. It gives an early measure of design size before physical implementation. Area matters because it affects manufacturing cost, routing congestion, power consumption and overall chip size.

### Report Configuration

| Item | Value |
|------|-------|
| Report | `synthesis/reports/area.rpt` |
| Top module | `execution_unit` |
| Technology library | 90 nm standard-cell library (`slow.lib`) |
| Library corner | slow |
| Wireload mode | enclosed |
| Operating condition | slow (balanced_tree) |

### Area Analysis Results

| Metric | Value |
|--------|-------|
| Cell Count | **5373** standard cells |
| Cell Area | **38190.146 µm²** |
| Net Area | 0.000 µm² |
| Total Area | **38190.146 µm²** |

> Area values are reported in µm².

### Explanation of Net Area

Net Area is the area attributed to wiring. Synthesis happens before placement and routing, so no physical wiring exists yet and the report shows `0.000`. Total Area is therefore equal to Cell Area. Wiring is only known after placement and routing in Cadence Innovus.

### Summary of Observations

- The complete Execution Unit was mapped to **5373 standard-cell instances** using the 90 nm library
- **Cell Area (38190.146 µm²)** is the total area of all synthesized standard cells
- **Net Area is 0.000**, so **Total Area equals Cell Area**
- Synthesis completed without errors
- This is a pre-layout figure and will be revisited after physical implementation

### Why Area Matters

| Impact | Relationship |
|--------|--------------|
| Manufacturing cost | Larger area means fewer dies per wafer |
| Routing congestion | More cells need more wiring |
| Power consumption | More cells add leakage and switching capacitance |
| Overall chip size | Cell area sets a lower bound on the chip size |
